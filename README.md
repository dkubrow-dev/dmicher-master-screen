# dmicher 🎬 Master screen | Ширма мастера

Ширма освобождает мастера от множества небольших, взаимосвязанных действий во время игры. Мастер готовит поведение объектов, игроки взаимодействуют с живой сценой, а решение о дальнейшем развитии игры остаётся за мастером.

**Версия разработки 0.0.1**, Foundry VTT **13 и 14**. Единственная обязательная зависимость — **dmicher-generics 1.0.0**, API 1. Premium, Spotlight и сторонние библиотеки не требуются. Удалённый релиз не опубликован.

## Начать работу

Включите Generics и Ширму в мире. Категория 🎬 слева открывает только подменю: справка, переключатель Ширмы, смена состояний, старт и стоп. «Ширма» открывает панель с сохранёнными размерами; повторное нажатие закрывает её. Штатные инструменты слоёв Foundry остаются доступны.

Конструктор и Режиссёр переключаются внутри Ширмы. Панель располагается справа или снизу, две её зоны изменяются перетаскиванием границ. Отделение в окно браузера и вызов Актёра находятся в верхней строке. Конструктор выделяет область карты красной рамкой.

Новая сцена не содержит групп. Создайте группу с первым состоянием, затем добавьте объекты и их подготовку. Группа — владелец объектов; состояние определяет их поведение. Группы запускаются и останавливаются независимо. Сохранение, открытие карты и переподключение ничего не запускают.

«Сменить состояние» изменяет только выбранные группы и сохраняет статус их автоматизации. «Старт» заново запускает все группы; «Стоп» возвращает ручное управление. Остановка не отменяет выполненные действия и не восстанавливает потраченные предметы.

## Объекты, инструменты и скрипты

«Информация» показывает имя, тип, ID и UUID с копированием и открывает штатные настройки. Здесь задаются группа, теги, заметки и флаг персонажа игрока. Один объект принадлежит одной группе; персонажу игрока группа не нужна.

В «Поведении» четыре вкладки:

- **Переходы** — исходный скрипт по явной команде мастера и отдельный скрипт входа в каждое состояние.
- **Особенности** — несколько магазинов и диалогов с условиями доступа по состояниям.
- **Рутина** — отдельный повторяемый или конечный скрипт каждого состояния.
- **Автоматизация** — сигналы объекта, прикреплённые макросы и подписки.

Общий редактор скриптов поддерживает ожидание, движение/поворот/размер, видимость, реплики, эмоции, звук, сигналы и макросы. ID шагов и переходы сохраняются при перестановке строк. В бою длительности расходуют бюджет хода; доступны подтверждение, пропуск и остановка скрипта в текущем бою. Вне поддерживаемого нативного поля размера Z оно не эмулируется высотой.

Магазины и диалоги — каталоги сцены. Один инструмент доступен с нескольких объектов; один магазин сохраняет общий запас и исключительную сессию игрока с персонажем. Подтверждение сделки повторно проверяет владение, остатки и ответы подписчиков. Пока открыто взаимодействие, рутина объекта приостановлена. Прерванный подписчиком диалог продолжается с сохранённой страницы.

В магазине передаются целые документы Item. Деление системных стопок, цены и валюты потребуют отдельных адаптеров. Предпросмотр не меняет мир, счётчики или запасы.

## Сигналы и макросы

Сигнал объявляется конкретным эмитентом и содержит типизированные параметры и возвраты. Дерево показывает группы, эмитентов и сигналы, затем объекты вне групп. Встроенные объявления сцены, боя, групп, магазинов и диалогов защищены; их можно дополнять собственными полями. Пользовательские имена допускают Unicode.

Подписчик исполняет только прикреплённый к нему макрос Foundry. Для подписки проверяется интерфейс без исполнения пользовательского поведения, затем результат проверяется при вызове. Отказ при валидации запуска, перехода или покупки отменяет предметное действие. Обычный вызов макроса скриптом не передаёт аргументы и не использует результат.

Контракты: [сигналы и группы](docs/signals-and-groups.md), [скрипты](docs/object-scripts.md), [каталоги и владение](docs/scene-assets-and-ownership.md), [взаимодействия](docs/dialogues-and-interactions.md), [структура кода](docs/refactor-0.0.1.md).

## Проверка и документация

Эксплуатационная справка RU/EN хранится в Ширме, интерфейс и общие стили предоставляет Generics. Значки вопроса открывают соответствующие настройки. Руководства: [первая сцена](docs/first-scene.md), [рабочий сценарий](docs/object-workflow.md), [панель](docs/constructor-panel.md), [магазин и Актёр](docs/shop-and-actor.md).

Синтетические тесты не создают объекты в пользовательских мирах. Браузерная проверка использует шаблоны и API Foundry 13/14. Она не заменяет сетевую проверку с несколькими игроками и конкретной системой.

```text
npm test
npm run deploy:dry-run
npm run deploy
npm run release:build
npm run release:verify
node --import ./scripts/esm-loader.mjs scripts/ide-browser-check.mjs
```

Перед деплоем проверяется точный план. Допустимы только каталоги модуля в AppData и двух установках Foundry 13/14. ZIP и отчёты находятся в `../artifacts/dmicher-master-screen/0.0.1/`. Манифест отдельного артефакта и ZIP идентичен и ссылается на точный предполагаемый релиз.

Текущий формат использует `groupDefinitions`, `groupRuntimes`, `signalCatalog`, `objectBindings` и `interactionCatalog`. Старые определения не преобразуются автоматически и не исполняются запасными реализациями. Миграции добавляются только по прямому запросу; файлы пользовательских миров не переписываются при разработке.

## Границы и комплект dmicher

Актёр — вспомогательный вид персонажа, а не полная копия клиента игрока. Импорт сцены создаёт новые документы, но медиафайлы переносятся отдельно; произвольные текстовые ссылки в макросах требуют проверки. Аварийная остановка блокирует следующие действия движка, но не может отменить выполненную операцию или насильно прервать произвольный JavaScript стороннего макроса.

Generics предоставляет общее оформление, окна, чат и мост Premium. Premium содержит лицензионную логику и дополнительные реализации; Spotlight управляет вниманием участников; сервер лицензий работает вне мира Foundry. Предметные правила Ширмы остаются в её репозитории. KISS и SOLID удерживают общие механизмы в границах конкретных потребителей. Внешние исполнители подключаются только явным выбором мастера.

Исследования и исходники конкурентов находятся в исключённой из Git папке `.resources/`. Они служат референсами для самостоятельной реализации и не входят в ZIP. Единственный `AGENTS.md` расположен в родительской рабочей папке. Репозиторий самостоятельный, ветка — `dev-masterscreen-0.0.1`, origin — `git@github.com:dkubrow-dev/dmicher-master-screen.git`.
