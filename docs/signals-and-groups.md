# Группы и сигналы

Документ для разработки. Эксплуатационные инструкции находятся во встроенной справке.

Группа владеет объектами и выбирает одно состояние. Определения хранятся в Scene.flags `groupDefinitions[groupId]`, исполнение — `groupRuntimes[groupId]`. Чтение пустой сцены ничего не создаёт. `entryStateId` обязателен. Изменение подготовки не начинает исполнение.

`GroupRuntime.enter` проверяет валидаторов до изменения состояния и повторно проверяет ревизию, запуск и барьер остановки после ответа. `preserveStatus` сохраняет работающий, остановленный или ещё не запущенный статус; `restart` начинает новый запуск. Старый результат не продолжает новый запуск. Сценовый lock охватывает чтение/запись фактов, но не исполняемый макрос.

## Каталог

`signalCatalog` содержит `signals`, `macros`, `subscriptions`. Эмитенты выводятся из существующих документов: `Scene:id`, `Combat:sceneId`, `Group:id`, `Shop:id`, `Dialogue:id`, `Token:id`, `Tile:id` и прочие нативные объекты. Подписка хранит `ownerKey`, `emitterKey`, `signalId`, `macroUuid`, `enabled`. Один и тот же документ Macro может быть явно прикреплён к нескольким объектам.

Сигнал содержит `id`, `emitterKey`, `name`, `description`, `parameters`, `returns`. Поля: `name`, `type` (`string`, `integer`, `number`, `boolean`), `nullable`, `default`, `description`, применимые ограничения длины/числа/точности. Имена пользовательских полей и сигналов не ограничиваются ASCII. Типы не приводятся неявно; `__proto__` остаётся обычным ключом данных.

Навигация группирует эмитентов по категориям Scene, Groups, Tokens, Tiles, Drawings, Walls, Other. Категории магазинов и диалогов — только представление, не новые общие эмитенты: каждое определение остаётся адресовано собственным ID. Выбор строки переиспользует компонент дерева сцены; выбранный нативный объект фокусируется без изменения документа.

`apps/signal-schema-fields.js` предоставляет общие раскрываемые таблицы полей для IDE и окна поведения объекта. Типовой редактор и JSON работают с одним черновиком; чтение перед сохранением учитывает ещё не применённый JSON. Системные поля неизменяемы в обоих представлениях. Пересоздание строки защищено от повторного change при потере фокуса. Раскрытие дерева сохраняется независимо от черновика.

Встроенные сигналы:

| Эмитент | Имена |
| --- | --- |
| Scene | activated, userEntered, userLeft, pauseChanged |
| Combat | combatStarted, turnChanged, roundStarted, combatEnded |
| Group | validateStart, started, validateTransition, transitioned |
| Shop | opened, beforePurchase, purchased, closed |
| Dialogue | opened, response, closed |

Точные типы и локализованные описания объявлены в `builtin-signals.js`. Дополнительные поля встроенного сигнала разрешены; автоматически вызываемым полям нужен default либо nullable. Системные поля не переопределяются. Валидации используют `allowed` и `message`: любой ответ, отличный от true, запрещает действие. В ответе диалога `interrupt` имеет приоритет над `exit`.

## Макрос подписки

Статическое объявление интерфейса хранится в JSON-комментарии `dmicher-signal-interface`; проверка синтаксиса и контракта при сохранении не вызывает макрос. Полный образец создаёт `signalMacroSnippet(signal)` и показывает редактор подписки.

Макрос возвращает объект `{ parameters, returns, async execute(context) }`. Каждое поле описывается как `{ type, nullable, value }`. Подмножество входов допустимо; лишний ожидаемый вход — ошибка. Все возвраты обязательны, включая nullable; дополнительные возвраты допустимы. При исполнении фабрика вызывается без аргументов, реальные определения сверяются со статическим контрактом, заполняются входные `value`, вызывается `execute`, затем читаются и проверяются возвраты.

Контекст обработчика даёт `scene`, `emitter`, `subscriber`, `signal`, `transition(groupId,stateId)`, `halt(groupId?)`, `emit(name,parameters)`. Последний метод испускает только собственный сигнал подписчика. Публичный GM API — `InvokeDmicherMasterScreenSignal(emitterKey,name,parameters)`.

Ошибки обработчиков диагностируются и не блокируют остальные подписки; ошибка валидатора запрещает действие. Цепочка ограничена 32 вложениями и 64 вызовами. Повтор ID вызова с теми же данными не исполняется второй раз в живом экземпляре; иной payload с тем же ID отвергается. Это локальная защита доставки, не транзакция произвольного пользовательского кода.

## Перенос

Экспорт содержит текущие определения, вложенные связи и необходимые объявления. При импорте групп/инструментов переназначаются ключи эмитентов и ID сигналов в подписках и скриптах. Полный импорт сцены сохраняет embedded ID, создаёт новые Actor/Macro/Journal документы и обновляет их ссылки. Исходная сцена не меняется; автоматизация импортированной сцены не запускается. Старые eventCatalog и прежние схемы не преобразуются.
