# Дополнительные действия скрипта — 0.0.1

## Выбор эмоций

Компактная палитра содержит четыре группы по 35 символов: смайлы, действия, символы эмоций и прочее. Каждая группа — 5 столбцов и 7 строк. Верхние значки ведут к разделам в прокручиваемой области; выбор переносится в поле и тот же JSON шага. Escape, выбор и клик снаружи закрывают окно. Закрытие формы освобождает обработчики и окно выбора.

Это прикладная подборка для мастера, а не статистический топ каждой категории. Частотная основа — опубликованные [данные Unicode 2019](https://home.unicode.org/emoji/emoji-frequency/); к ним добавлены понятные сигналы внимания, одобрения, запрета и состояния. Все 140 уникальных последовательностей проверены как fully-qualified по [официальному Emoji 12.0](https://www.unicode.org/Public/emoji/12.0/emoji-test.txt). Такой базовый набор выбран для широкой поддержки шрифтами. Подписи RU/EN описывают смысл выбора; стандарт [UTS #51](https://unicode.org/reports/tr51/) определяет последовательности символов. Внешние изображения и библиотеки не используются.

`emotion.parameters` содержит `emoji`, `size`, `duration`. `size` — конечное число больше нуля, включая дроби; значение по умолчанию 32 задаёт размер шрифта в пикселях карты. Это размер шрифта, а не точная граница рисунка глифа. Масштаб карты влияет на символ обычным образом. Прогресс сохраняет размер рядом с эмоцией; при выборе последней эмоции выбирается и её размер. JSON и таблица используют одни параметры.

## Действие State

Формат: `state.parameters.transitions = [{groupId, stateId}]`. Каждая группа встречается не более одного раза. Пустой список — допустимое бездействие. Таблица показывает названия групп и состояний; JSON хранит ID. Удалённое назначение видно как недоступное и не подменяется автоматически.

Общий исполнитель `changeStates` обслуживает скрипт и ручной диалог. До записи проверяются существование всех назначений, разрешающие сигналы и актуальность подготовки. Переключение сохраняет статус запуска каждой группы и общий стоп сцены. Текущее состояние пропускается; собственная группа вызывающего объекта переключается последней. После этого прежнее исполнение не может перейти к следующему шагу. Ручное вмешательство останавливает оставшиеся переходы; уже совершённые действия не откатываются.

Ссылки `transitions` принадлежат схеме данных. Импорт группы переводит ссылки на эту группу к новой группе. Импорт одного состояния переводит только выбранную пару. Внешние назначения сохраняются и проверяются до записи. Столкновение двух пар на одну группу после переноса отклоняется. Параметры сигналов и тела макросов остаются непрозрачными.

## Диалог

`dialogue.parameters = {dialogueId, tokenUuids: [], waitMode: "all"}`. Выбор ограничен собственными прикреплёнными диалогами объекта. Перед запуском набора проверяются UUID токенов этой сцены, активные владельцы персонажей, доступность привязки и суммарная кратность. Для каждого персонажа выбирается один явный владелец; сначала назначенный `User.character`, затем стабильный порядок владельцев. Неявные права мастера и технический пользователь не делают их адресатами.

Используются настоящие игровые сессии: их открывает исполняющий мастер, после чего приватное техническое сообщение приглашает клиент владельца показать уже созданную сессию. Клиент проверяет автора, адресата, права и актуальность сессии. Окно не повторяет команду старта и расход кратности. Предпросмотр и ручной показ остаются отдельными режимами. Скриптовый запуск диалога доступен в переходах и рутине запущенной группы; восстановление исходного состояния вручную его не запускает и объясняет ограничение. Для показа без автоматизации используется окно «Диалоги».

Если пауза, чужое взаимодействие или смена боевого хода прерывают открытие набора, незавершённое исполнение ждёт допуска и сохраняет уже созданные сессии. Оно продолжает доставку и открытие оставшихся участников после возобновления; старты не повторяются. Остановка группы или сцены отменяет продолжение. Переподключение не воспроизводит незавершённые побочные действия.

- `all` — дождаться закрытия всех начатых разговоров (по умолчанию).
- `first` — дождаться первого завершившегося разговора, независимо от порядка UUID.
- `none` — продолжить скрипт после открытия окон.

Остальные окна не закрываются автоматически. Завершающий текст остаётся открытым до «Уйти», закрытия окна или истечения срока сессии; прерванный разговор также требует закрытия. Только точные ID сессий, начатых этим исполнением, исключаются из его общей паузы взаимодействия. Торговля, другой разговор и другие скрипты сохраняют обычную паузу. Смена состояния и аварийный стоп имеют приоритет над поздним ответом.

При scoped импорте `dialogueId` переносится как ссылка каталога `Dialogue`, а UUID персонажей — как известные ссылки сцены. Произвольные JSON-поля не переписываются. Если экспорт одного состояния оставляет скрипт, чей диалог доступен лишь в другом состоянии, экспорт отклоняется с предложением экспортировать группу целиком; доступность не расширяется автоматически.

## Приблизиться и следовать

`approach.parameters = {targetUuid, distance: 0, timeMode: "duration", duration: 0, speed: 5}`. Действие располагается после «Перемещение». Расстояние считается между нативными границами объектов, 0 означает касание. Цель читается в начале шага: её последующее движение не превращает действие в преследование. Прямая намеренно игнорирует препятствия. Длительность по умолчанию 0; в режиме скорости время рассчитывается по пути и скорости в единицах сцены в секунду.

`follow.parameters = {targetUuid, minDistance: 0, maxDistance: 5, speed: 5, mode: "trajectory", finishOn: "arrival"}`. За пределами максимального расстояния объект догоняет до минимального; внутри диапазона ожидает или заканчивает шаг. При слишком близкой цели объект не отступает автоматически. `trajectory` сохраняет опорные точки перемещения цели, `direct` движется прямо; оба режима учитывают доступные нативные коллизии Foundry. Обхода препятствий и поиска пути нет. Буфер траектории ограничен, коллинеарные точки объединяются, переполнение диагностируется вместо потери углов.

`finishOn: "arrival"` завершает шаг при достижении цели (в том числе если допустимая дистанция уже достигнута при старте). `state-change` сохраняет следование до смены состояния или остановки исполнения. UUID должен указывать на поддерживаемый другой объект текущей сцены. Действия используют общий договор времени, приостановки взаимодействием, отмены и бюджета боевого хода.

Таблицы параметров и JSON редактируют один объект. Режим скрывает неприменимые поля, сохраняя их значения. Повторный `change` после редактирования JSON не пересоздаёт неизменившуюся таблицу: первый клик по её кнопке остаётся рабочим.
