# Личная сортировка и взаимодействие объектов

Сортировка основной зоны — представление мастера. `NavigationOrder` переставляет существующие DOM-строки вместе с дочерними строками, без рендера формы и записи подготовки сцены. Порядок хранится в localStorage по миру, пользователю, сцене, вкладке и родительской строке; Конструктор и Режиссёр используют один порядок. Стрелки Alt+↑/↓ работают с рукояткой строки. Новые записи добавляются после известных. Перенос состояния между группами сохраняет отдельный явный диалог копирования/перемещения и не подменяется сортировкой.

## Команды

Команда не требует общей группы у действующего объекта и цели. При делегировании условия `conditions.groups` относятся к группе и текущему состоянию исполнителя поручения, при прямой команде игрока — его персонажа. Пустой список не ограничивает группу. Существующие проверки прав источника, владения, тегов, доступности и остановки исполнения сохраняются.

В проверке сигнала команды у объекта без группы прежде использовался синтетический идентификатор как идентификатор запуска группы. `SceneSignals` не находил такую группу и считал проверку устаревшей даже при отсутствии подписчиков. Теперь для такого объекта проверяется отменяемый контекст сцены без вымышленного запуска группы. Смена идентичности исполнения или остановка по-прежнему отменяет проверку.

Общая геометрия `commandInteractionDistance` применяется как при допуске, так и после движения поручения. Для стены используется ближайшая точка сегмента, для прочих объектов — их нативный центр. Если движение остановилось перед препятствием в пределах дальности команды цели, поручение передаётся цели. Если дальности не хватает, сохраняется отказ о перекрытом пути. Перед передачей проверяются актуальные настройки цели; препятствия не игнорируются.

## Персонажи игроков

`objectCapabilities(type, binding)` определяет доступность собственных магазинов и диалогов. Для персонажа игрока они отсутствуют в окне «Автоматизация», в предложениях собственных шагов, в интерактивном меню, в подготовке состояния и при скриптовом запуске. Ограничение относится к владельцу инструмента: посещение магазинов и диалогов других объектов сохраняется. Сохранённые назначения не удаляются при чтении и не мигрируются.

## Проверка

- Модульные проверки: сортировка ветвей, персональные ключи, без записи сцены; команды к восьми нативным типам без группы; разные группы; группа фактического исполнителя; остановка в пределах/за пределами дальности.
- Сквозное исполнение: поручение → подход → проверка сигнала → открытие двери → завершение обоих запусков, для цели без группы и в другой группе, с препятствием и без него.
- Браузерные стенды Foundry 13.351 и 14.366, RU/EN: перетаскивание, клавиатура, сохранение черновика, иерархия, смена режима и перезагрузка; вкладки «Автоматизации» персонажа игрока.

Стенды используют синтетические документы. Пользовательская сцена не изменяется проверками.
