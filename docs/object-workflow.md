# Подготовка поведения объекта

В Конструкторе выберите активный слой Foundry и кликните объект. Контекстное меню предлагает **Информацию** и **Поведение**. Другие инструменты Foundry не закрывают Ширму. Все действия подготовки выполняются на объектах, которые мастер создаёт самостоятельно штатными средствами.

## Информация

Нередактируемые значения показаны в порядке: название, тип, ID, UUID, Actor UUID. Рядом с каждым — маленькая кнопка копирования. **Настройки** открывает штатное окно соответствующего документа. Затем идут **Персонаж игрока** (для токена), группа, теги и заметки. Размер окна учитывает содержимое; при недостатке места работает прокрутка.

Enter сохраняет и закрывает форму, Shift+Enter добавляет строку заметки. Сохранение меняет только изменённые поля. Назначение группы создаёт общую запись владения, которую показывает таблица группы. Перед переназначением остановите затронутые группы. Неназначенный объект допустим; удалённую со сцены привязку можно убрать из группы без обращения к отсутствующему документу.

Флаг **Персонаж игрока** по умолчанию снят. Он отключает автоматизацию токена и позволяет взаимодействовать с объектами любых групп без собственной группы. Проверки владения Actor, видимости, расстояния и условий сохраняются.

## Переходы

Первый блок — **Исходное состояние**. Это отдельный скрипт для явного восстановления объекта к началу приключения. В нём можно задать движение, поворот, размеры и видимость. Кнопка восстановления сохраняет подготовку и явно запускает этот скрипт. Чтение документа и переподключение его не запускают. Восстановление предметов, здоровья и иных игровых фактов не подразумевается.

Далее таблица **Состояния** содержит все состояния группы. Для подготовленного перехода видны имя скрипта, изменение и удаление; для пустой строки — прочерк и создание. Выбор открывает редактор под таблицей. Скрипт перехода исполняется при явном входе в соответствующее состояние. **Сохранить** оставляет блок редактирования открытым.

## Особенности

Магазины и диалоги имеют отдельные таблицы состояний. В каждой строке можно добавить нужные инструменты. Один объект допускает несколько магазинов и диалогов, в том числе разные наборы в разных состояниях. Настройка привязки содержит выбранный каталог, дальность и условия: активность, состояния, белый/чёрный списки тегов, кратность и сброс счётчика. Пустой список состояний означает доступность во всех состояниях группы.

Условия принадлежат назначению объекта; ассортимент и остатки принадлежат магазину. Несколько объектов одного магазина разделяют исключительную торговую сессию. При нескольких доступных инструментах контекстное меню показывает их имена.

## Рутина и общий редактор скрипта

Таблица рутины также содержит все состояния. Один скрипт рутины на состояние создаётся только явно; отсутствие скрипта означает отсутствие рутины. Исходное состояние, переход и рутина используют один редактор: название, включение, шаги, повторение и настройки боя при его поддержке.

Функции шагов: ожидание, движение, видимость, реплика, эмоция, звук, сигнал и макрос. Параметры вводятся по предложенному JSON-шаблону. Для движения есть выбор точки на карте, для звука — FilePicker Foundry, для эмоции — набор символов и возможность задать своё значение. Списки сигналов и макросов содержат только объявления и прикрепления этого объекта.

ID шагов и переходы определяют исполнение; визуальная перестановка строк их не меняет. Запуск и повторение начинаются с ID 1. Пустой переход завершает скрипт; несколько целей выбираются случайно. Перетащите ручку строки либо используйте Alt+↑/↓. Сохранение сохраняет порядок чтения и очищает ссылки на удалённые цели, не перенумеровывая остальные шаги.

В бою можно включить выполнение в ход объекта, подтверждение действий, уведомления, завершение хода и его длительность. Длительные действия учитывают оставшееся время; ручное перемещение между ходами меняет исходную позицию продолжения, сохраняя подготовленную цель. Мастер может продолжить, пропустить текущий ход или остановить скрипт до конца боя.

Открытая торговля или диалог приостанавливает рутину. После закрытия всех взаимодействий выполнение продолжается с сохранённого остатка времени без повторения выполненных действий. Остановка группы и ручное отключение объекта имеют приоритет.

## Автоматизация

В начале находятся сигналы объекта, затем его макросы и подписки. Сигналы можно добавлять, редактировать и удалять; системная часть защищена. Макросы перетаскиваются из Foundry, создаются и редактируются штатным редактором. Список показывает проверки и скрипты, использующие макрос.

Подписка связывает прикреплённый объекту макрос с его собственным или чужим сигналом в этой сцене. При сохранении проверяются типы входа и возврата. Если интерфейса нет, форма показывает заготовку для кода. Проверка при настройке не выполняет тело макроса. Ошибки исполнения сообщаются мастеру по правилам режима и не останавливают интерфейс Ширмы.

Исходные документы мира автоматически не переводятся из прежних форматов. Миграции выполняются только по отдельному запросу владельца проекта.
