# Конфигурации окон и заметок

Подготовка хранится в `Scene.flags.dmicher-master-screen.workspacePresets`: `{schemaVersion:1,revision,windows:[],notes:[]}`. Каталог изменяется явно, с проверкой ревизии. Чтение и захват не создают документов и не пишут флаги. Имена уникальны в пределах вида конфигурации. Автоматических миграций нет.

`workspace-presets-model.js` содержит чистую нормализацию и перенос известных ссылок. `workspace-presets-store.js` записывает каталог через очередь сцены. `workspace-presets-runtime.js` управляет применением; `workspace-window-adapter.js` взаимодействует с нативными окнами. `apps/workspace-presets-view.js` формирует обе зоны IDE и читает черновик, не обращаясь к исполнительной среде.

## Окна

Каждый элемент хранит `id,name,target,x,y,width,height,minimized,hidden,closeOnLeave`. Цель — документ по UUID или приложение по зарегистрированному ID. Конфигурация дополнительно содержит `activeWindowId,sidebarTab,closeUnmanaged`. Общий механизм открытия ApplicationV1/V2 переиспользуется из `workspace.js`; старые рабочие столы состояний пока имеют отдельный договор владения и не подменяются конфигурациями.

Адаптер не конструирует классы из сохраняемых строк. Документ открывается через `fromUuid().sheet` после проверки доступа; для окон модулей используются явные фабрики `runtime.windows.register(id,{match,open})`. Фабрика должна возвратить приложение и проверять переданный `isCurrent` перед асинхронным открытием. Прочие уже открывавшиеся окна можно переоткрыть по сохранённому экземпляру текущего клиента. После перезагрузки отсутствие фабрики вызывает понятную ошибку; прежняя конфигурация при этом не закрывается.

Сначала проверяются ссылки назначения; затем закрываются отмеченные окна предыдущего набора, отсутствующие в новом. `closeUnmanaged` дополнительно закрывает открытые окна, отсутствующие одновременно в предыдущем и новом наборах. Снятый `closeOnLeave` удерживает окно. Отмена конфигурации закрывает только отмеченные окна этого набора. Ручное перемещение/закрытие не меняет активность и не пишет подготовку; явное повторное применение возвращает план. Активный снимок хранится в localStorage отдельно для пользователя и мира, без автоматического применения при загрузке.

## Заметки

Элемент хранит `id,name,data,sourceId,sourceSceneId,removeOnLeave`. `data` — исходные поля Note без нативного ID и служебной метки владения. Захват содержит ссылки на существующие заметки только как подсказку первого применения в той же сцене. Явное применение принимает исходную заметку под управление либо создаёт новую; помечает её `flags.dmicher-master-screen.workspacePreset={version:1,presetId,entryId}`. Повторное применение находит уже созданную заметку по этой метке и не дублирует её. При переходе удаляются только документы с совпадающей меткой и включённым `removeOnLeave`. Непривязанные заметки и документы, у которых вручную изменилось владение, не удаляются.

`workspaceNotesRuntime={presetId,entries:[{id,noteId,removeOnLeave}]}` сохраняет активный снимок для продолжения после перезагрузки. Это состояние исполнения, его не следует включать в перенос подготовки. Перенос конфигураций обрабатывает UUID окон и `entryId/pageId` заметок; подсказки исходных Note в другую сцену не переносятся. Произвольные флаги других модулей не переписываются по совпадению имён полей.

## Исполнение и отмена

`activate(scene,kind,idOrName,{isCurrent})` и `deactivate` сериализуют операции отдельно для окон клиента и заметок каждой сцены. Новый запрос отменяет оставшиеся стадии прежнего. Поздний результат создания заметок удаляет только документы, созданные этой отменённой операцией. Уже отправленную запись Foundry физически отменить нельзя. Остановка не откатывает действия, успевшие завершиться. `dispose` инвалидирует операции, но не закрывает уже представленные окна и не удаляет заметки.

Настройка и явное применение доступны мастеру/ассистенту через штатное `isGM`. Скриптовый вызов дополнительно передаёт проверку принадлежности действующему исполнению. Никаких перерисовок на кадрах движения, фоновых обходов или наблюдателей геометрии этот механизм не создаёт.

Проверки: `node --import ./scripts/esm-loader.mjs --test tests/workspace-presets.test.js tests/workspace.test.js`.
