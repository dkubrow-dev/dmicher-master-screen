# Структура разработки 0.0.1

Код использует группу, состояние, объявленный сигнал и общий скрипт. Заменённые реализации событий/типов триггеров и отдельные исполнители старого поведения удалены. Форматы не преобразуются при чтении. Исследовательские снимки в `.resources` не являются частью продукта.

Generics остаётся общей инфраструктурой стилей, окон, справки и чата. В него не переносятся группы, сигналы Ширмы, скрипты, предметные условия или лицензирование. Premium подключается через мост Generics. Новых сторонних библиотек для этой модели нет.

## Границы слоёв

Модель принимает обычные данные и возвращает нормализованный результат или отказ. Она не открывает окна, не создаёт документы и не записывает флаги. Предметные операции получают снимки каталогов и явно подготавливают связанные изменения. Адаптер хранения выражает удаления карт через нативную семантику Foundry; маркеры удаления не становятся бизнес-данными.

Контроллер связывает исполнение с отображением. Движок передаёт состояния эмоций и облачков адаптеру `visuals`, который владеет PIXI-объектами и освобождает их при удалении документа или закрытии сцены. Конструктор редактирует скрипты через отдельные операции над шагами; перестановка строк сохраняет ID и переходы. Общая форма владеет обработчиками DOM, несохранёнными полями и обработкой ошибок, но не предметными командами.

Похожие случаи объединены по ответственности. Магазин с ожидающим решения предложением удерживает сессию без истечения срока; прерванный диалог снимает паузу рутины, а открытая последняя страница удерживает её до окончания аренды. Эти различия описаны рядом в модели сессий, а не спрятаны в универсальном исполнителе.

Страницы диалогов в подготовке, исполнении и ручном просмотре используют `pages`, `startPageId`, `nextPageId`. Поле `nodeId` в уже действующем протоколе разговорной сессии и версия 1 сохранённых приглашений остаются стабильными. Их преобразование ограничено транспортной границей. Это сохранение текущего договора, а не миграция прежних форматов мира.

Перенос меняет только объявленные ссылки в известной структуре. Пользовательские JSON-параметры и тела макросов остаются непрозрачными: поля с именами `signalId`, `groupIds` или `stateIds` не дают права переписывать их содержимое. Идентификаторы каталогов сопоставляются с учётом типа (`Shop:id` и `Dialogue:id`).

Отдельный действующий договор полного экспорта сцены — перенос известных UUID документов Foundry. Он заменяет точные UUID и их вложенные ссылки во всём экспортируемом документе, включая пользовательские значения по умолчанию. Это не тот же механизм, что переименование внутренних ID сигналов. Текст, целиком совпадающий с переносимым UUID, также считается ссылкой; описание и символ из этого прохода исключены.

## Локализация

Общий модуль локализации Ширмы выбирает RU/EN для интерфейса и диагностик. Встроенные описания имеют обе языковые версии, пользовательские названия и тексты сохраняются дословно. HTML-разметка остаётся в представлениях, переводы не исполняются как код. Эксплуатационная справка хранится отдельно от этой документации.

Проверки покрывают строгие типы, исключительное владение, независимые группы, await-подписки без взаимоблокировок, прерывание, повторное ожидание после глубокого слияния флагов, неизменяемые ID шагов, торговые остатки и перенос текущих связей. Браузерные сценарии используют синтетические документы и локальные приложения Foundry 13/14.

Проверка интерфейса макроса не исполняет код. Произвольный код мастера запускается только при разрешённом выполнении. Его уже совершённые побочные действия не откатываются аварийной остановкой; запоздавшее продолжение не получает права на новые действия Ширмы.
