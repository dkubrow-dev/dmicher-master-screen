# Рефакторинг раннего черновика — 10 сентября 2026

Поддерживаемая модель подготовки имеет четыре явных владельца:

| Данные | Владелец |
| --- | --- |
| Схемы, эпизоды, входные действия, зоны и рабочие окна | `model.js`, `store.js`, `scheme-editor.js` |
| Общие магазины и диалоги сцены | `scene-assets.js` |
| Принадлежность объекта схеме, размещение, допуск инструментов, рутина и реакции объекта | `scene-objects.js` |
| Типизированные события, триггеры, подписки и зарегистрированные макросы | `event-catalog.js` |

`materializeEpisode` собирает отдельный снимок исполнения из этих определений. Его списки объектов, диалогов, рутин и подписок особенностей — результат сборки, а не второй редактируемый источник. `runtime.js` управляет жизненным циклом схемы; `routine-runtime.js` исполняет шаги объекта. Сохранение подготовки не запускает действия и не изменяет уже исполняемый снимок.

Удалены прежний редактор поведения токена, отдельный эпизодный редактор диалога, старый граф разрешений переходов, патруль и периодическая речь прежнего формата. Их задачи решают редактор объекта, каталоги, события эпизодов и таблица рутины. Уникальные инструменты эпизода — зоны, прямые действия, пауза, звук, подкрепления и рабочие окна — остаются в `episode-tools.hbs`. Редактор выводит выбранный блок непосредственно, без извлечения фрагмента из большой скрытой формы.

Магазин и диалог используют `gm-request.js` для общего запроса мастеру через чат: адресация, сопоставление ответа и освобождение подписки. Проверка автора, прав, предметов, допуска и сессий остаётся в соответствующих сервисах. Транспорт не повторяет команду при неизвестном исходе. Это внутренний код Ширмы с двумя потребителями; предметные правила не переносятся в Generics.

## Сохранение состояния рутины

Foundry сливает вложенные флаги. Удаление `remainingMs` через обычный `delete` из локального снимка не удаляло ранее сохранённый остаток. Следующее ожидание могло использовать время предыдущего шага. Теперь переход сбрасывает остаток явно, а `waitStepId` связывает его с конкретным ожиданием. Запись runtime также передаёт штатные маркеры удаления отсутствующих ключей только внутри своей схемы, чтобы завершённые сессии и временные поля не возвращались после слияния.

Синтетическая проверка воспроизводит глубокое слияние Foundry и два цикла ожиданий 7 и 10 секунд. Пауза взаимодействия по-прежнему сохраняет остаток текущего ожидания. Установленные факты мира не сбрасываются при переподключении.

## Порядок строк

Порядок массива `steps` задаёт отображение таблицы. ID и `next` определяют исполнение; старт и повтор используют ID 1. Перетаскивание строки и Alt+↑/↓ сохраняют ID, переходы и незавершённый ввод. При сохранении отсутствующие цели удаляются, остальные ссылки не перенумеровываются. Непустой блок требует ID 1; интерфейс объясняет запрет его удаления, пока существуют другие шаги.

## Правило миграций

Миграции добавляются только по прямому запросу пользователя. В этом черновике удалены чтение одиночных старых флагов, автоматическое создание каталогов из прежних эпизодов, старые варианты инструментов и конверсия патрулей. Поддержка штатных API Foundry 13/14 и адаптация текущих данных к представлению окна не являются миграциями.

Исходные документы миров при рефакторинге не переписывались. Импорт/экспорт обслуживает текущий формат подготовки. Старые поля не восстанавливают удалённые реализации автоматически.
