# Исполнение каталогов взаимодействий

Каталог сцены хранит содержание магазинов и диалогов. Привязка `objectBindings.bindings['Type:id']` определяет единственного владельца-схему, эпизоды допуска, дальность и триггер. Один магазин может обслуживаться через несколько Token/Tile: у него один остаток и одна занятая сессия в пределах сцены.

## Команды и проверки

`getShopContext(sceneId, target, schemeId)` принимает `{type:'Token'|'Tile', id}`; строковый ID — сокращённая адресация Token. `requestSession`, `renewSession`, `updateOffer`, `releaseSession`, `requestTrade` передают `target`, `shopId`, `actorTokenId`, `schemeId`, `runId`; обмен дополнительно передаёт `sessionId`, `requestId`, `giveItemIds`, `take`. Переданный `shopId` не выбирает магазин самостоятельно: исполнитель повторно разрешает привязку объекта.

Сессия принадлежит конкретному User, Token и Actor. На открытии и продолжении проверяются актуальный запуск, активность схемы/эпизода, привязка объекта, владение персонажем, дальность, прямая видимость, уровень сцены и теги. Кратность расходуется только на открытии новой сессии. Общий `shopId` блокируется между схемами; смена официанта не переносит существующую сессию незаметно. Мастер может отменить сохранённую сессию даже после снятия её привязки: отмена не передаёт предметы.

Остатки сохраняются в `Scene.flags.dmicher-master-screen.shopInventories[shopId]`, сессии и квитанции — в состоянии их исходной схемы. Новый эпизод сохраняет ожидающие решения сессии и квитанции. Неопределённый результат требует ручной сверки и не повторяется автоматически. Единица передачи — целый документ Item: неизвестные системные поля количества и валют не интерпретируются. Подтверждение повторно проверяет весь обмен; при ошибке выполняется доступная компенсация с сохранением неопределённого результата, если её нельзя подтвердить.

Поле количества товара в каталоге задаёт **начальный запас**. После появления товара в действующем магазине сохранённые Item и остаток считаются фактами мира: изменение начального количества не пополняет существующую позицию, а удаление позиции из подготовки не уничтожает её текущий запас. Это также сохраняет вещи, которые игроки передали магазину, хотя их не было в исходном каталоге. Новая позиция с новым ID добавляется с заданным начальным запасом; правка данных уже существующего ID не заменяет предметы в текущем инвентаре. Перед первым запуском ассортимент и начальные количества следует подготовить полностью. Отдельное управление пополнением и списанием текущих запасов планируется позже; автоматического сброса при редактировании или входе в эпизод нет.

Торговая команда содержит только ID имеющейся позиции и требуемое число целых Item. Переданные клиентом данные предмета и заявленный остаток не используются. Исполнитель проверяет ID и количество по текущему инвентарю, объединённому с новыми подготовленными позициями; неизвестная или исчерпанная позиция отклоняется до изменения мира.

`requestStart({sceneId, dialogueId, target, actorTokenId, schemeId, runId})` открывает общий диалог через конкретный объект. Продолжение использует сохранённые Actor, target и запуск, а также ожидаемые номер шага и страницу. ID ответа выбирается только из текущей страницы. События испускаются после освобождения блокировки сцены. «Уйти» не испускает событие завершения. Один каталоговый диалог у двух объектов сохраняет раздельные условия и источник события.

`openManualDialogue({sceneId, dialogueId, pageId?})` показывает каталоговый диалог мастеру без привязки к объекту или запущенной схеме. Ручное приглашение игроков передаёт только представление и локальную навигацию: оно не включает автоматизацию, не расходует триггер и не испускает событие.

## Чтение и репетиция

`listAvailableInteractions(scene, target, actorToken, user)` возвращает доступные `shop`, `dialogue` и `interaction`. Метод не записывает флаги и не расходует счётчики. Каждая последующая команда проверяет условия заново.

`evaluateInteractionPreview({config,kind,schemeId,episodeId,tags,distance,visible,enabled,used,halted})` возвращает `{allowed,reason}` по выбранным условиям. Это чистая репетиция на временных значениях: нет доступа к текущим сессиям, изменения документов, чата или исполнения событий. Отсутствие реальной привязки и выбор доступного каталога проверяет вызывающий интерфейс через `resolveObjectShop`/`resolveObjectDialogue`.

## Вход и остановка

`entryEpisodeId` выбирает эпизод по умолчанию для явной команды `runtime.enter(scene, undefined, {schemeId})`. Открытие карты, переключение активной сцены и переподключение ничего не запускают. Начальные параметры каждого назначенного объекта отмечаются в `objectEntries['Type:id']` до изменения документа и применяются один раз. Параметры объекта для эпизода применяются при каждом явном входе. Ручные изменения сохраняются до следующего такого входа.

Объектовые подписки особенностей перед исполнением проверяют наличие объекта, текущую схему-владельца, активность особенности и ручное отключение токена. При аварийной остановке новый вызов не начинает работу; уже начатую операцию Foundry невозможно отменить атомарно. Для торговли исполнитель повторяет проверку после ожиданий и до следующей операции с предметами.

Макрос объектовой особенности дополнительно получает в `scope` поля `objectTarget` (`{type,id}` владельца подписки), `sceneObject` (его актуальный документ Foundry) и `featureId` (ID особенности). `event` также содержит `objectTarget` и `featureId`, но не документ. Исходный типизированный `trigger` не изменяется. Один макрос у нескольких НПС таким образом различает владельца конкретной подписки и источник входящего события; обычные сценовые макросы не получают эти дополнительные поля.

Исполнитель использует текущие явные каталоги и привязки. Чтение не создаёт инструментов из прежних настроек и не преобразует старые идентификаторы. Расходованные остатки текущего магазина адресуются его `shopId`.

Открытые взаимодействия удерживают распорядок исходного токена. Последняя страница диалога остаётся открытой до ухода, закрытия или истечения сессии; событие завершения при продлении не повторяется. Подробности сроков, паузы и восстановления ожидания — в [token-routines.md](token-routines.md).
