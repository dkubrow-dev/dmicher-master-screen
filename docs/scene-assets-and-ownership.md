# Каталоги и владение объектами

Сцена хранит отдельные `interactionCatalog.shops` и `interactionCatalog.dialogues`. У каждого инструмента собственные ID, имя и подготовка. `objectBindings.bindings["Type:id"]` — единственная запись принадлежности нативного объекта группе и встречной таблицы объектов группы. Считывание не создаёт групп или объектов.

Привязка содержит `groupId`, `playerCharacter`, `tags`, `notes`, `initialScript`, `transitionScripts`, `scripts`, `shops`, `dialogues`. Скрипты принадлежат назначению и состоянию. В массивах магазинов и диалогов каждая строка хранит ID инструмента, `stateIds`, `range`, `conditions`. Пустой список состояний означает все состояния группы. В одном состоянии допускаются несколько разных инструментов; повторный одинаковый инструмент не создаёт дубликатов меню.

Смена владельца требует остановки затронутых групп и явного согласия на переназначение. При этом сохраняются заметки, теги и исходный скрипт, а прежние скрипты состояний и особенности очищаются. Player character исключает объект из автоматизации. Token и Tile поддерживают взаимодействия; остальные нативные объекты доступны для информации и поддерживаемых скриптовых операций.

Удалённый нативный объект можно отвязать без обращения к отсутствующему документу. Удаление последней группы разрешено, последнего состояния существующей группы — нет. Удаление состояния очищает его зависимости в текущих привязках; это предметная операция редактирования, не миграция старого формата.

`materializeState` собирает подготовку одного состояния из единственных источников: определения группы, каталога и привязок. Сохранённые факты запаса магазина и ручное отключение объекта не восстанавливаются из подготовки при переходе.

Изменение структуры флагов учитывает глубокое слияние Foundry: пропущенные ключи карт удаляются директивами `-=`, поля прогресса сбрасываются явно. Простое удаление свойства копии не считается гарантией удаления данных.

Экспорт группы или состояния включает связанные инструменты, сигналы и подписки; импорт предварительно проверяется на подготовленной копии, включая конфликт владельцев. Старые token-config и eventCatalog не реконструируются. Миры пользователя не преобразуются при обновлении кода.
