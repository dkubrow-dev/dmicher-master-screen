# Распорядок токена и пауза взаимодействий

Распорядок принадлежит токену и одному эпизоду его схемы. Мастер готовит таблицу шагов; сохранение не запускает её. При явном входе в эпизод исполнение начинается с шага ID 1. По умолчанию таблица пуста. Движение, реплики, ожидания и эмоции токена задаются шагами одного распорядка.

Шаг имеет постоянный положительный целый `id`, `kind`, объект `parameters` и список `next`. Порядок массива определяет только положение строк в редакторе: перетаскивание не изменяет ID и связи. Новый шаг получает `max(id) + 1`; непустой распорядок обязательно содержит ID 1. Удаление строки удаляет ссылки на неё, но не перенумеровывает остальные шаги. Несколько следующих номеров означают равновероятный выбор одного из них. Пустой список завершает распорядок; при `repeat: true` исполнение возвращается к ID 1. За один такт выполняется не более 16 мгновенных шагов, поэтому цикл эмоций не блокирует интерфейс.

| Вид | Параметры | Поведение |
| --- | --- | --- |
| `wait` | `seconds` — положительное дробное число | Ждать указанное число секунд игрового исполнения. |
| `move` | `x`, `y`, `speed` | Двигаться к координатам карты; скорость в единицах расстояния сцены за секунду. Стена или ошибка изменения документа останавливает распорядок с объяснением. |
| `speech` | `text`, `chat`, `bubble` | Отправить реплику в чат и/или показать её над токеном. Чат получают мастера и владельцы персонажей в пределах 30 единиц расстояния, имеющих прямую видимость. Пузырь показывается штатным механизмом Foundry только там, где токен виден. Текст экранируется. |
| `emotion` | `emoji` | Установить символ над токеном; пустая строка снимает символ. |
| `event` | `eventName`, `triggerId`, `parameters` | Проверить объявленный тип триггера и передать событие в очередь сцены. |
| `macro` | `macroUuid`, `parameters` | Выполнить зарегистрированный скриптовый макрос Foundry с заданными параметрами. |

Подготовка хранится в `objectBindings.bindings["Token:id"].routines`. Материализованный снимок эпизода содержит `episode.routines` с `target`. `runtime.routineStates[tokenId]` хранит текущий шаг, его статус, остаток ожидания, номер одноразового действия и текущую эмоцию. `waitStepId` связывает остаток с конкретным ожиданием. Переход явно записывает `remainingMs: null` и `waitStepId: null`; отсутствие поля при глубоком слиянии флагов Foundry не считалось бы удалением. Движение продолжает путь из актуальных координат документа. Обычное переподключение сохраняет прогресс; время отсутствия клиента не догоняется.

Внешнее действие сначала получает сохраняемую отметку `pending`, затем выполняется вне очереди записи Scene. Если новый клиент видит такую отметку без собственного выполняемого задания, результат считается неизвестным (`uncertain`): действие не повторяется, мастер проверяет факты и явно перезапускает эпизод. Ошибка шага не вызывает бесконечную серию повторных попыток. Обычная пауза Foundry, ручное отключение токена и аварийная остановка останавливают дальнейшие шаги. Только выбранный активный полный ГМ выполняет распорядки.

Макрос получает `actor`, `token`, `scene`, `episode`, `runId`, `parameters`, `stepId`, `objectTarget: {type: "Token", id}` и `sceneObject` — документ токена. Локальная `InvokeDmicherMasterScreenEvent` сохраняет принадлежность исходному запуску; после остановки, смены эпизода или во время взаимодействия её вызов отклоняется. Ожидание незавершающегося макроса отвязывается при остановке или уходе со сцены. Уже начатый произвольный JavaScript не прерывается насильно, а уже отправленные сообщения и выполненные изменения не отменяются.

## Диалог и торговля удерживают НПС на месте

После проверки автора команда открытия ставит временную локальную паузу **до** ожидания очереди Scene. Проверка актуального положения, условий и сохранение сессии выполняются внутри этой очереди. Ранее начатое изменение документа может завершиться; проверка использует уже его результат. Следующий шаг движения не может обогнать открытие взаимодействия. Отклонённая команда освобождает временную паузу.

Сохранённые сессии удерживают паузу по исходному токену. Один НПС может одновременно обслуживать торговлю и несколько разговоров разных персонажей; пауза снимается, когда закончилась последняя сессия. Пауза останавливает распорядок и сохраняет остаток ожидания; после возобновления нет рывка движения или наверстывания пропущенных реплик. Признак `playerCharacter` полностью исключает токен как источник автоматизации, но не запрещает его владельцу взаимодействовать с другими объектами, даже без назначения персонажа в схему.

Последняя страница диалога, в том числе единственная страница без ответов, остаётся взаимодействием до «Уйти», закрытия окна или истечения сессии. Событие завершения разговора отправляется один раз; продление чтения не повторяет событие. Окно каждые 30 секунд продлевает сессию на 120 секунд. При обрыве соединения или потере условий доступ не продлевается; по истечении срока НПС продолжает работу. Повторное открытие своей незакрытой сессии того же запуска, объекта и персонажа восстанавливает срок после проверки условий без повторного расхода кратности. Закрытие окна во время ещё не завершённого открытия освобождает сессию, как только приходит результат. Ручной показ диалога мастером после остановки остаётся отдельным режимом без событий и без запуска автоматики.

Торговое предложение, ожидающее решения мастера, удерживает существующую сессию до решения или ручного освобождения. После явного запуска нового эпизода предложение прежнего запуска остаётся для разбора мастером и не допускает новой торговли до освобождения, но больше не приостанавливает новый распорядок. Общие остатки магазина и его исключительность не меняются от паузы движения.

Проверки: `tests/routine-runtime.test.js` включает многократные ожидания 7 и 10 секунд при глубоком слиянии флагов, принадлежность остатка текущему шагу и старт с ID 1 при другом порядке строк. `runtime`, `catalog-interactions`, `shop`, `dialogues`, `events`, `scene-design` и `multi-scheme-ui` проверяют текущее исполнение и взаимодействия. Адаптер реплик использует `ChatBubbles.broadcast` из локальных исходников Foundry 13.351 и 14.366; дополнительные библиотеки не нужны. Миры пользователя при проверке не изменяются.
